# 동아리 신청·배정

스포츠클럽·동아리 QR 신청·균등 배정 (1차 MVP)

`클로드_인수인계_동아리배정_MVP.md`를 기준으로 만든 **가상 데이터 데모**입니다.

**교사가 모집 개설 → QR 안내 → 학생 희망 제출 → 교사가 배정 버튼 클릭 → 결과 확인·명단 내려받기**

## 실행

Node.js 22.13 이상이 필요합니다(이 PC는 v26). 외부 서비스·DB 설치는 필요 없습니다.

```bash
npm install
```

```bash
npm run demo
```

```bash
npm start
```

- `npm run demo` : 가상 학교(학생 24명·프로그램 4개, 접수 중)를 만들고, 교사 계정과 학생코드를 `data/demo-accounts.txt`에 적습니다.
- `npm start` : 서버 실행. 교사 화면은 <http://localhost:3000/teacher>(주소만 쳐도 여기로 갑니다), 학생은 교사 화면의 QR(또는 그 옆 주소)로 바로 신청 화면에 들어옵니다. 화면은 PC·휴대전화 너비에 맞춰 자동으로 바뀝니다.
- 같은 와이파이의 휴대전화로 QR을 찍으려면 Windows 방화벽에서 3000번 포트 접속을 허용해야 할 수 있습니다.
- 데이터는 `data/` 폴더(SQLite 파일)에 저장됩니다. 지우면 처음 상태가 됩니다.
- 글꼴은 Pretendard(SIL OFL 1.1)를 npm 패키지로 설치해 서버가 직접 내려줍니다. 외부 글꼴 서버에 접속하지 않습니다.

| 환경 변수 | 뜻 |
| --- | --- |
| `PORT` | 포트(기본 3000) |
| `PUBLIC_BASE_URL` | QR에 넣을 주소(예: `https://club.example.kr`). 없으면 접속한 주소/내부 IP 사용 |
| `SIGNUP_CODE` | 설정하면 이 코드를 아는 사람만 학교 공간을 만들 수 있음 |
| `SECURE_COOKIE=1` | HTTPS 뒤에서 실행할 때 쿠키에 Secure 적용 |

## 사용 흐름

**운영교사** — 화면 맨 위 "지금 할 일" 카드만 따라가면 됩니다.

1. 준비: 명부를 엑셀 파일(.xlsx)·CSV로 넣거나 엑셀에서 복사해 붙여넣기(표기는 자동 인식, 아래 참고) → 프로그램 입력 후 `인원 균등하게 나누기` → 학생코드 발급(배부용 쪽지 인쇄) → `접수 시작`
2. 접수 확인: 제출/미제출 수, 미제출 명단, 필요하면 `대신 입력`(누가 입력했는지 기록, 확인 방법은 선택) → `접수 마감`
3. 배정·확정: `배정하기` → 검증 결과 확인 → `결과 확정·공개` → 프로그램별/학급별 명단(CSV, 엑셀에서 열림)

**학생** — QR 접속 → 학년·반·번호 + 개인 신청코드 → 1지망(필수)·2·3지망(선택) → 접수번호 확인 → 발표 후 같은 주소에서 본인 결과 확인. 이메일·계정이 필요 없습니다.

## 입장 방법 (모집마다 선택)

준비 단계의 **③ 입장 방법**에서 고릅니다. 학교마다, 같은 학교라도 모집마다 다르게 쓸 수 있습니다. 접수를 시작한 뒤에는 바꿀 수 없습니다.

| 입장 방법 | 학생이 입력하는 것 | 교사가 할 일 | 대리 신청을 막는 힘 |
| --- | --- | --- | --- |
| 학번 + 이름 + 입장 번호 | 학년·반·번호, 이름, 4자리 번호 | 칠판에 번호 하나 적기 | 번호를 아는 사람끼리는 못 막음 |
| 학번 + 이름 | 학년·반·번호, 이름 | 없음 | 가장 약함 |
| 개인 신청코드 (기본값) | 학년·반·번호, 8자리 코드 | 학생마다 쪽지 배부 | 가장 강함 |

- **첫 접속 기기 고정**(켜고 끄기): 한 학번으로 처음 들어온 기기만 계속 쓸 수 있습니다. 다른 기기에서 들어오려 하면 막고, 교사의 미제출·제출 명단에 "다른 기기 시도"로 표시합니다. 교사가 **기기 풀기**를 누르면 다음에 들어오는 기기가 새로 고정됩니다(신청 내용은 그대로).
- 입장 번호는 서버가 만들고 교사 화면에만 보입니다. 학생에게 공개되는 정보에는 들어가지 않습니다.
- 어떤 방법이든 여러 번 틀리면 그 학번만 5분간 잠깁니다.
- 기기 고정은 브라우저 쿠키로 기기를 구분합니다. 학생이 쿠키를 지우거나 시크릿 창·다른 브라우저로 들어오면 다른 기기로 보고 막으므로, 그때는 교사가 풀어 줘야 합니다.
- 지문·얼굴 인증은 넣지 않았습니다. "등록해 둔 그 기기가 맞다"만 확인해 줄 뿐 처음에 누가 누구인지는 알려 주지 못하고, HTTPS가 필요하며 공용 기기에서는 쓸 수 없기 때문입니다.

## 접수 시작 예약

준비 단계의 **시작·마감 시각 · 설정** 카드에서 "시작 예약"과 "마감 시각"을 정하고 저장하면, 맨 위 버튼이 **접수 예약**으로 바뀝니다. 누르면 그 시각에 자동으로 열리고 마감 시각에 자동으로 닫힙니다. 엑셀 양식의 [설정] 시트에도 "시작 시각" 줄이 있습니다.

- 예약 시각 전에 들어온 학생은 입장해서 기다릴 수 있지만 신청은 받지 않습니다. 화면에 "11/20 18:00 시작"이 보이고, 시각이 되면 새로 고치지 않아도 신청 화면으로 바뀝니다.
- 따로 도는 예약 작업은 없습니다. 요청이 올 때마다 서버 시각으로 "지금 열려 있는가"를 판정합니다. 그래서 **그 시각에 서버(이 프로그램을 실행한 컴퓨터)가 켜져 있고 학생이 접속할 수 있는 주소여야 합니다.** 교실 PC에서 실행해 두고 퇴근하면서 PC를 끄면 열리지 않습니다. 퇴근 뒤 집에서 신청받으려면 학교 밖에서도 접속되는 서버(호스팅)에 올려야 합니다.
- 시작 시각은 마감 시각보다 앞이어야 합니다. 예약을 취소하려면 접수 중 화면의 "← 준비 단계로 돌아가기"로 돌아가 시각을 고칩니다.

## 단계 되돌리기

| 지금 단계 | 할 수 있는 것 |
| --- | --- |
| 접수 중 | **접수 마감**(미제출이 있어도 마감됨) · **← 준비 단계로 돌아가기** |
| 준비(접수 멈춤) | 명부·프로그램·참여 제한·입장 방법 수정 · **접수 시작**으로 이어서 받기 |
| 접수 마감 | **← 접수 중으로 돌아가기** · **← 준비 단계로 돌아가기** · 미제출 대신 입력 · **배정하기**(미제출이 있어도 가능) |
| 준비 | **초기화하기**: 명부·프로그램·참여 제한·받은 신청을 모두 지움(되돌릴 수 없음). 모집 이름과 설정은 남음 |
| 배정 검토 | **← 접수 마감으로 돌아가기**: 배정 결과를 지우고 마감으로 돌아감. 미제출로 배정했던 학생은 다시 미제출. 신청이 그대로면 다시 배정해도 같은 결과 |
| 결과 공개 | **← 공개 전으로 돌아가기**: 학생 화면에서 결과가 사라지고 배정 검토로 돌아감. 배정 결과는 그대로라 다시 공개할 수 있음 |

- **지난 단계는 돌아가지 않고도 볼 수 있습니다.** 위쪽 단계 줄에서 지난 단계(준비·접수 중·마감·배정 검토)를 누르면 그때 적은 명부·프로그램·입장 방법·설정·안내문과 접수 내용을 보기 전용으로 보여 줍니다. 고칠 수는 없고, 모집 상태도 바뀌지 않습니다. "지금 단계로"를 누르면 돌아옵니다.
- **준비 단계로 돌아가 있는 동안** 학생은 들어와서 자기 신청을 볼 수 있지만 고치거나 새로 낼 수 없습니다("잠시 멈춤").
- **고쳐도 신청은 남습니다.** 명부는 학년·반·번호가 같은 학생을 그대로 두고(신청·학생코드·접속 유지) 새 학생만 더하며, 빠진 학생만 지웁니다. 프로그램은 이름이 같으면 그대로 둡니다.
- **영향받은 신청만 미제출로 돌아갑니다.** 없앤 프로그램이나 새로 건 참여 제한 때문에 지망에 고를 수 없는 프로그램이 생긴 학생은 미제출이 되고, 몇 건인지 알려 줍니다. 순위를 대신 당겨 주지는 않습니다(학생이 다시 고르거나 교사가 확인해 대신 입력). 추첨 기준은 바뀌지 않습니다.
- **미제출이 있어도 배정할 수 있습니다.** 배정하기를 누르면 "미제출 N명을 포함해 배정할까요?"를 묻고, 확인하면 미제출 학생은 지망 단계에 참가하지 않고 남은 자리에 무작위로 배정됩니다. 그렇게 처리했다는 것이 학생별 신청 기록과 작업 기록에 남고, 학생 화면에는 "접수 완료"가 아니라 "신청하지 않음 · 남은 자리 배정"으로 나옵니다. 그 전에 "대신 입력"으로 희망을 넣어 줄 수도 있습니다.
- 접수 시작·마감·배정·공개 등을 누르면 화면 안에 확인 창이 뜹니다(브라우저 기본 확인 창은 환경에 따라 뜨지 않아 쓰지 않음).

## 결과 명단 보기·내려받기

- **학생에게는 배정된 프로그램과 장소만** 보입니다. 몇 지망으로 배정됐는지, 남은 자리였는지는 교사 화면에서만 봅니다.
- 교사 화면의 명단은 **반별 / 프로그램별**로 묶어 보고, 한 반·한 프로그램만 골라 볼 수 있습니다.
- **명단 내려받기**는 형식을 고른 뒤 학급별·프로그램별을 누릅니다.

| 형식 | 내용 |
| --- | --- |
| 엑셀 (.xlsx) | 첫 시트는 전체, 그다음부터 반(또는 프로그램)마다 시트 하나 |
| PDF (.pdf) | PDF 파일을 바로 내려받습니다. 반(또는 프로그램)마다 한 쪽씩 나오고(40명 안팎까지 한 쪽), 글꼴이 파일 안에 들어 있어 어느 기기에서 열어도 한글이 그대로 보입니다 |
| 한글 (.hwpx) | 한컴오피스 한글 문서. 반(또는 프로그램)마다 새 쪽에서 시작하는 표 |
| CSV | 예전과 같은 한 장짜리 표 |

예시 파일(가상 명단): `docs/명단_예시/`

## 학생 안내 팝업과 결과 열람 기간

- **입장 전 안내 팝업**: 학생이 QR로 들어오면 입장하기 전에 팝업이 뜹니다. 신청 마감 시각, 들어오는 방법(모집의 입장 방법에 맞춰 자동), 고르는 방법, 배정 방식이 나오고, 교사가 적은 안내문(600자 이내)이 그 아래에 붙습니다. 안내문은 준비·접수 중 화면의 "학생 안내 팝업"에서 언제든 고칠 수 있습니다. 학생은 "안내 다시 보기"로 다시 열 수 있습니다.
- **결과 공개**: 교사가 "결과 공개"를 눌러야 공개됩니다. 학생은 같은 QR 주소에서 본인 결과만 봅니다. 발표 뒤 화면에는 배정된 프로그램, 배정 과정, 내가 낸 희망 목록, 접수번호가 함께 나옵니다.
- **열람 종료 시각**(선택): 배정 검토·결과 공개 화면에서 정합니다. 그 시각부터는 학생이 들어와도 "열람 기간이 끝났습니다"만 보입니다. 비워 두면 기한 없이 볼 수 있고, 나중에 늦추거나 없앨 수 있습니다. 교사 화면의 명단과 내려받기는 기간과 상관없이 남습니다.

## 엑셀 양식으로 한 번에 준비

준비 단계의 **① 양식 받기**로 엑셀 양식(.xlsx)을 내려받아 적은 뒤 **② 작성한 양식 올리기**를 누르면, 읽은 내용을 먼저 보여 주고 **한 번에 적용**합니다. 빈 양식은 [docs/동아리_신청배정_양식.xlsx](docs/동아리_신청배정_양식.xlsx)에도 있습니다.

| 시트 | 적는 것 |
| --- | --- |
| 작성 방법 | 안내만 있음(읽지 않음) |
| 학생 명단 | 학년 / 반 / 번호 / 이름 |
| 프로그램 | 프로그램 이름 / 설명 / 장소·준비물 / 배정 인원 / 최대 인원. 배정 인원을 비우면 학생 수에 맞춰 고르게 나눔 |
| 설정 (선택) | 문의처, 마감 시각(예: 2026-11-20 16:00) |
| 참여 제한 (선택) | 학년 / 반 / 번호 / 이름 / 참여할 수 없는 프로그램 |

- 이미 입력한 명단·프로그램이 있으면 양식에 채워져 내려옵니다. 고쳐서 다시 올리면 됩니다.
- 하나라도 틀린 곳이 있으면 아무것도 바뀌지 않습니다(전부 적용되거나 전부 그대로).
- 적은 시트만 바뀝니다. 프로그램 시트만 적어 올리면 명단은 그대로입니다.
- 양식이 아닌 자기 엑셀을 올려도 명단은 아래 "명부 자동 인식"으로 읽습니다.
- 양식 파일은 구조 검증(압축·XML·패키지)을 통과했고, 사용자가 엑셀에서 정상적으로 열리는 것을 확인했습니다(2026-11-12). 엑셀에서 작성·저장한 파일을 다시 올리는 왕복과 한셀에서의 동작은 아직 확인하지 않았습니다.

## 명부 자동 인식

엑셀 파일(.xlsx)·CSV(UTF-8, 엑셀 한글 CSV)·붙여넣은 표를 읽어 "학년, 반, 번호, 이름"으로 맞추고, **등록 전에 읽은 결과를 먼저 보여 줍니다.**

| 엑셀에 담긴 모양 | 예 |
| --- | --- |
| 칸이 나뉜 표 | 학년 / 반 / 번호 / 이름. 열 순서가 달라도, 연번·성별·생년월일·보호자 칸이 섞여도, 제목 줄이 없어도 읽음. `1학년`·`01`·`5번` 표기도 읽음 |
| 학번 한 칸 | `1학년 1반 5번`, `10105`, `1105`, `1-1-5`, `1.1.5`, `10,105` |
| 학년·반이 한 칸 | `1-3`, `1학년 3반`, `103` + 번호 칸 |
| 반·번호가 한 칸 | 학년 칸 + `3-12`, `0312`, `3반 12번` |
| 한 줄에 전부 | `1학년 1반 5번 김하늘`, `10105 김하늘`, 반별 표의 `5. 김하늘` |
| 반별 명렬표 | 제목 줄 "2026학년도 1학년 3반 학생 명부"나 시트 이름 "1-3"에서 학년·반을 읽음 |
| 병합된 칸 | 학년·반이 빈 줄은 윗줄 값을 이어받음 |
| 좌우로 나란한 표 | 번호 / 이름 / 번호 / 이름 |
| 반이 가로로 놓인 표 | 번호 / 1반 / 2반 / 3반 (칸 안이 이름). 번호 칸이 없으면 위에서부터 순서대로 매기고 그렇게 했다고 알림 |
| 학년(반)이 아예 없는 파일 | 화면에서 한 번 물어 채움 |

- 이름은 `(전입)`·`*` 같은 표시를 떼고, `김 하 늘`처럼 띄어 쓴 이름은 붙입니다. 전출·휴학 표시가 있는 줄은 포함하되 몇 명인지 알려 줍니다.
- 합계·담임 줄, 이름이 빈 줄은 건너뜁니다.
- **짐작하지 않는 값**: `115`(1-1-5인지 1-15인지 모름), 엑셀이 날짜로 바꿔 버린 학번(예: `1-1-5` → `36896`), 범위를 벗어난 숫자, 같은 학년·반·번호의 중복, `가반`·`A반`처럼 숫자가 아닌 반. 이런 줄은 줄 번호와 함께 알려 주고, 하나라도 있으면 등록할 수 없습니다.
- 옛 엑셀(.xls)·한글(.hwp)·PDF는 읽지 못합니다. xlsx로 저장하거나 표를 복사해 붙여넣으세요.
- 파일은 교사의 브라우저 안에서만 읽고, 서버에는 맞춘 결과(학년·반·번호·이름)만 보냅니다.

## 구현한 내부 보호 장치

- 학교 격리: 모든 교사 API가 로그인한 교사의 학교에 속한 모집인지 서버에서 확인(다른 학교는 404). 학생 ID는 세션에서만 결정.
- 학생코드: 서버 보안 난수 8자리(헷갈리는 글자 제외), 서버에는 검증값(HMAC)만 저장, 원문은 발급 직후 한 번만 제공, 재발급 시 이전 코드·세션 폐기.
- 추첨 기준: 접수 시작 때 서버 보안 난수로 한 번 생성·보존, 교사가 고르거나 다시 뽑을 수 없음. 모집당 검증된 배정 실행은 1개(DB 유일성 제약).
- 신청: `(학교, 모집, 학생)` 유일성 제약, 요청 식별자 멱등 처리, 버전 확인, 제출 이력 보존, 서버 저장 뒤에만 '접수 완료' 표시.
- 결과: 비공개로 전부 저장·검증한 뒤 활성 결과 포인터를 한 트랜잭션으로 전환.
- 기타: 응답 `no-store`, CSP, 쿠키 HttpOnly·SameSite=Strict, 다른 출처 요청 거부, 화면은 textContent로만 출력, 주요 동작 기록(`audit_log`).

- **HTTPS**: 서버 자체는 http입니다. 실제 사용 시 HTTPS 프록시/호스팅 뒤에 두어야 합니다(그 전에는 코드·세션이 암호화되지 않음).
