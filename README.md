# 찜콩

스포츠클럽·동아리 QR 신청·균등 배정 (1차 MVP)

`클로드_인수인계_동아리배정_MVP.md`를 기준으로 만든 **가상 데이터 데모**입니다.

**교사가 모집 개설 → QR 안내 → 학생 희망 제출 → 교사가 배정 버튼 클릭 → 결과 확인·명단 내려받기**

## 이름과 글꼴

- 이름은 **찜콩**입니다. 이름에는 동글(Dongle) 글꼴을, 본문에는 Pretendard를 씁니다. 둘 다 SIL 오픈 폰트 라이선스 1.1이며 `npm install`로 함께 설치됩니다.
- 디자인 후보를 검토한 페이지는 `docs/찜콩_디자인/후보_검토.html`에 있습니다.

## 실행

Node.js 22.13 이상이 필요합니다(이 PC는 v26). 외부 서비스·DB 설치는 필요 없습니다.

```bash
npm install
```

```bash
npm run demo
```

```bash
npm start
```

- `npm run demo` : 가상 학교(학생 24명·프로그램 4개, 접수 중)를 만들고, 교사 계정과 학생코드를 `data/demo-accounts.txt`에 적습니다.
- `npm start` : 서버 실행. 교사 화면은 <http://localhost:3000/teacher>(주소만 쳐도 여기로 갑니다), 학생은 교사 화면의 QR(또는 그 옆 주소)로 바로 신청 화면에 들어옵니다. 화면은 PC·휴대전화 너비에 맞춰 자동으로 바뀝니다.
- 같은 와이파이의 휴대전화로 QR을 찍으려면 Windows 방화벽에서 3000번 포트 접속을 허용해야 할 수 있습니다.
- 데이터는 `data/` 폴더(SQLite 파일)에 저장됩니다. 지우면 처음 상태가 됩니다.
- 글꼴은 Pretendard(SIL OFL 1.1)를 npm 패키지로 설치해 서버가 직접 내려줍니다. 외부 글꼴 서버에 접속하지 않습니다.

| 환경 변수 | 뜻 |
| --- | --- |
| `PORT` | 포트(기본 3000) |
| `PUBLIC_BASE_URL` | QR에 넣을 주소(예: `https://club.example.kr`). 없으면 접속한 주소/내부 IP 사용 |
| `SIGNUP_CODE` | 설정하면 이 코드를 아는 사람만 학교 공간을 만들 수 있음 |
| `SECURE_COOKIE=1` | HTTPS 뒤에서 실행할 때 쿠키에 Secure 적용 |

## 사용 흐름

**운영교사** — 화면 맨 위 "지금 할 일" 카드만 따라가면 됩니다.

1. 준비: 명부를 엑셀 파일(.xlsx)·CSV로 넣거나 엑셀에서 복사해 붙여넣기(표기는 자동 인식, 아래 참고) → 프로그램 입력 후 `인원 균등하게 나누기` → 학생코드 발급(배부용 쪽지 인쇄) → `접수 시작`
2. 접수 확인: 제출/미제출 수, 미제출 명단, 필요하면 `대신 입력`(누가 입력했는지 기록, 확인 방법은 선택) → `접수 마감`
3. 배정·확정: `배정하기` → 검증 결과 확인 → `결과 확정·공개` → 프로그램별/학급별 명단(CSV, 엑셀에서 열림)

**학생** — QR 접속 → 학년·반·번호 + 개인 신청코드 → 1지망(필수)·2·3지망(선택) → 접수번호 확인 → 발표 후 같은 주소에서 본인 결과 확인. 이메일·계정이 필요 없습니다.

## 입장 방법 (모집마다 선택)

준비 단계의 **③ 입장 방법**에서 고릅니다. 학교마다, 같은 학교라도 모집마다 다르게 쓸 수 있습니다. 접수를 시작한 뒤에는 바꿀 수 없습니다.

| 입장 방법 | 학생이 입력하는 것 | 교사가 할 일 | 대리 신청을 막는 힘 |
| --- | --- | --- | --- |
| 학번 + 이름 + 입장 번호 | 학년·반·번호, 이름, 4자리 번호 | 칠판에 번호 하나 적기 | 번호를 아는 사람끼리는 못 막음 |
| 학번 + 이름 | 학년·반·번호, 이름 | 없음 | 가장 약함 |
| 개인 신청코드 (기본값) | 학년·반·번호, 8자리 코드 | 학생마다 쪽지 배부 | 가장 강함 |

- **첫 접속 기기 고정**(켜고 끄기): 한 학번으로 처음 들어온 기기만 계속 쓸 수 있습니다. 다른 기기에서 들어오려 하면 막고, 교사의 미제출·제출 명단에 "다른 기기 시도"로 표시합니다. 교사가 **기기 풀기**를 누르면 다음에 들어오는 기기가 새로 고정됩니다(신청 내용은 그대로).
- 입장 번호는 서버가 만들고 교사 화면에만 보입니다. 학생에게 공개되는 정보에는 들어가지 않습니다.
- 어떤 방법이든 여러 번 틀리면 그 학번만 5분간 잠깁니다.
- 기기 고정은 브라우저 쿠키로 기기를 구분합니다. 학생이 쿠키를 지우거나 시크릿 창·다른 브라우저로 들어오면 다른 기기로 보고 막으므로, 그때는 교사가 풀어 줘야 합니다.
- 지문·얼굴 인증은 넣지 않았습니다. "등록해 둔 그 기기가 맞다"만 확인해 줄 뿐 처음에 누가 누구인지는 알려 주지 못하고, HTTPS가 필요하며 공용 기기에서는 쓸 수 없기 때문입니다.

## 접수 시작 예약

준비 단계의 **시작·마감 시각 · 설정** 카드에서 "시작 예약"과 "마감 시각"을 정하고 저장하면, 맨 위 버튼이 **접수 예약**으로 바뀝니다. 누르면 그 시각에 자동으로 열리고 마감 시각에 자동으로 닫힙니다. 엑셀 양식의 [설정] 시트에도 "시작 시각" 줄이 있습니다.

- 예약 시각 전에 들어온 학생은 입장해서 기다릴 수 있지만 신청은 받지 않습니다. 화면에 "11/20 18:00 시작"이 보이고, 시각이 되면 새로 고치지 않아도 신청 화면으로 바뀝니다.
- 따로 도는 예약 작업은 없습니다. 요청이 올 때마다 서버 시각으로 "지금 열려 있는가"를 판정합니다. 그래서 **그 시각에 서버(이 프로그램을 실행한 컴퓨터)가 켜져 있고 학생이 접속할 수 있는 주소여야 합니다.** 교실 PC에서 실행해 두고 퇴근하면서 PC를 끄면 열리지 않습니다. 퇴근 뒤 집에서 신청받으려면 학교 밖에서도 접속되는 서버(호스팅)에 올려야 합니다.
- 시작 시각은 마감 시각보다 앞이어야 합니다. 예약을 취소하려면 접수 중 화면의 "← 준비 단계로 돌아가기"로 돌아가 시각을 고칩니다.

## 단계 되돌리기

| 지금 단계 | 할 수 있는 것 |
| --- | --- |
| 접수 중 | **접수 마감**(미제출이 있어도 마감됨) · **← 준비 단계로 돌아가기** |
| 준비(접수 멈춤) | 명부·프로그램·참여 제한·입장 방법 수정 · **접수 시작**으로 이어서 받기 |
| 접수 마감 | **← 접수 중으로 돌아가기** · **← 준비 단계로 돌아가기** · 미제출 대신 입력 · **배정하기**(미제출이 있어도 가능) |
| 준비 | **초기화하기**: 명부·프로그램·참여 제한·받은 신청을 모두 지움(되돌릴 수 없음). 모집 이름과 설정은 남음 |
| 배정 검토 | **← 접수 마감으로 돌아가기**: 배정 결과를 지우고 마감으로 돌아감. 미제출로 배정했던 학생은 다시 미제출. 신청이 그대로면 다시 배정해도 같은 결과 |
| 결과 공개 | **← 공개 전으로 돌아가기**: 학생 화면에서 결과가 사라지고 배정 검토로 돌아감. 배정 결과는 그대로라 다시 공개할 수 있음 |

- **접수 중에도 마감 시각을 바꿀 수 있습니다.** 접수 중 화면의 "마감 시각 바꾸기"에서 늦추거나 당깁니다(접수를 멈추지 않음). 마감 시각이 지나면 학생 쪽은 저절로 닫히고, 교사 화면에 "마감 시각이 지났습니다"가 뜹니다.
- **모집 삭제**: 모집 화면 맨 아래 "모집 삭제". 명부·프로그램·신청·배정 결과가 모두 지워지고 학생 QR·주소도 열리지 않습니다(되돌릴 수 없음). 끝난 모집의 학생 정보를 정리할 때 씁니다.
- **지난 단계는 돌아가지 않고도 볼 수 있습니다.** 위쪽 단계 줄에서 지난 단계(준비·접수 중·마감·배정 검토)를 누르면 그때 적은 명부·프로그램·입장 방법·설정·안내문과 접수 내용을 보기 전용으로 보여 줍니다. 고칠 수는 없고, 모집 상태도 바뀌지 않습니다. "지금 단계로"를 누르면 돌아옵니다.
- **준비 단계로 돌아가 있는 동안** 학생은 들어와서 자기 신청을 볼 수 있지만 고치거나 새로 낼 수 없습니다("잠시 멈춤").
- **고쳐도 신청은 남습니다.** 명부는 학년·반·번호가 같은 학생을 그대로 두고(신청·학생코드·접속 유지) 새 학생만 더하며, 빠진 학생만 지웁니다. 프로그램은 이름이 같으면 그대로 둡니다.
- **영향받은 신청만 미제출로 돌아갑니다.** 없앤 프로그램이나 새로 건 참여 제한 때문에 지망에 고를 수 없는 프로그램이 생긴 학생은 미제출이 되고, 몇 건인지 알려 줍니다. 순위를 대신 당겨 주지는 않습니다(학생이 다시 고르거나 교사가 확인해 대신 입력). 추첨 기준은 바뀌지 않습니다.
- **미제출이 있어도 배정할 수 있습니다.** 배정하기를 누르면 "미제출 N명을 포함해 배정할까요?"를 묻고, 확인하면 미제출 학생은 지망 단계에 참가하지 않고 남은 자리에 무작위로 배정됩니다. 그렇게 처리했다는 것이 학생별 신청 기록과 작업 기록에 남고, 학생 화면에는 "접수 완료"가 아니라 "신청하지 않음 · 남은 자리 배정"으로 나옵니다. 그 전에 "대신 입력"으로 희망을 넣어 줄 수도 있습니다.
- 접수 시작·마감·배정·공개 등을 누르면 화면 안에 확인 창이 뜹니다(브라우저 기본 확인 창은 환경에 따라 뜨지 않아 쓰지 않음).

## 지난 모집과 겹치지 않게 (1학기·2학기)

같은 프로그램을 다시 여는 모집에서, 학생이 지난번에 배정받은 프로그램을 또 받지 않게 합니다.

- 준비 단계 맨 아래 **"겹치지 않게"** 카드에서 지난 모집을 고르고 저장합니다.
- 그 모집에서 배정받은 프로그램은 **이름이 같으면** 그 학생에게서 빠집니다. 학생 화면의 목록에서도 사라지고, 배정에서도 받지 않습니다.
- 학생은 학년·반·번호와 이름으로 맞춥니다. 학년이 바뀌어 학번이 달라진 학생은 맞춰지지 않습니다.
- 프로그램 이름을 조금이라도 다르게 적으면 다른 프로그램으로 봅니다(띄어쓰기·대소문자 차이는 무시).
- 이 설정으로 배정한 뒤에는, 기준이 된 모집의 배정을 먼저 취소할 수 없습니다(뒤 모집의 배정부터 취소).

## 신청 방식: 희망 조사·추첨 / 선착순

모집마다 준비 단계에서 신청 방식을 고릅니다.

| 방식 | 학생 화면 | 배정 |
| --- | --- | --- |
| 희망 조사 · 추첨 | 1~3지망을 골라 제출(제출 전 확인 팝업) | 마감 뒤 지망 순서대로, 정원이 넘으면 추첨 |
| 선착순 · 1~3지망 | 1~3지망을 적어 "신청". 내는 순간 1지망부터 자리가 있는 곳으로 바로 신청되고("신청 완료 · 2지망 배드민턴"), 고른 곳이 모두 찼으면 남은 곳에서 다시 고름 | 잡은 자리는 그대로 확정, 신청하지 않은 학생만 남은 자리에 무작위 |
| 선착순 | 예매처럼 프로그램마다 "신청 가능 · 남은 n자리" 또는 "마감". 누르면 확인 팝업 뒤 바로 "신청에 성공하였습니다" | 잡은 자리는 그대로 확정, 신청하지 않은 학생만 남은 자리에 무작위 |

- 선착순은 지망을 적지 않습니다. 다른 프로그램을 누르면 먼저 잡은 자리가 풀리고 새 자리로 옮겨집니다.
- 선착순은 정원 합계가 학생 수 이상이면 됩니다(추첨 방식은 인원 합계가 학생 수와 같아야 함).
- 선착순은 개인 신청코드로 들어올 수 없어 학번+이름(또는 입장 번호)으로 바뀝니다.
- 추첨 ↔ 선착순으로 바꾸면 받아 둔 신청은 모양이 달라 지워집니다(바꾸기 전에 묻습니다). 선착순 두 방식 사이는 그대로 둔 채 오갑니다. 접수를 시작한 뒤에는 바꿀 수 없습니다.
- 자유학기 묶음은 항상 선착순이고, 학생 화면도 같은 예매 방식입니다.

## 자유학기 묶음 (한 화면 준비 · 선착순)

한 학기에 1기·2기로 나누어 주제선택·진로탐색을 여러 번 듣고, 같은 영역에서 같은 프로그램을 두 번 듣지 않게 할 때 씁니다.
일반 모집(지망 추첨)과 달리 **먼저 신청한 순서로 자리가 정해지는 선착순**입니다.

**준비 (묶음 화면 한 곳에서)**
새 모집에서 **"자유학기"**를 켜고 기 수만 정해 만들면 묶음 화면이 열립니다. 모집 목록에는 묶음 이름 한 줄만 보입니다.

| 칸 | 넣는 것 |
| --- | --- |
| ① 구성 | 기 수, 반 나누기. 수업 시간이 다른 학급 무리가 있으면 나눕니다(예: A반 = 1~4반, B반 = 5~8반). 나누지 않으면 모든 학급이 한 반입니다 |
| ② 명부 | 한 번만 넣습니다. 반 나누기대로 자동으로 갈립니다 |
| ③ 주제선택 · ④ 진로탐색 | 수업 표. **한 줄이 수업 하나**(프로그램 · 요일·교시 · 반 · 정원 · 장소)입니다. 같은 프로그램이 A반·B반에 따로 열리면 두 줄로 적습니다. 엑셀에서 붙여넣을 수 있습니다 |
| ⑤ 설정 | 입장 방법(학번+이름 / 입장 번호), 시작·마감 시각, 문의처, 안내문 |

- **정원은 수업 하나의 한 기 인원**입니다. 같은 수업이 기마다 반복되므로 1기에 20명, 2기에 20명이 듣습니다.
- 저장하면 **시간대가 자동으로** 만들어집니다: 기 × 영역 × 반 × 요일·교시. 예) `1기 주제선택 월2,3 · A반`
- 맨 위 점검이 모두 통과해야 "접수 시작"을 누를 수 있습니다. 반·시간마다 정원 합계가 그 반 학생 수 이상이어야 하고, 한 시간에 열리는 프로그램 종류가 기 수 이상이어야 합니다.
- 접수를 시작한 뒤 구성을 고치려면 묶음 화면의 "모두 준비 단계로"로 되돌린 뒤 고칩니다. 이미 잡은 자리는 남습니다.

**학생 신청 (한 화면)**
- 묶음 QR 하나로 들어와 본인 확인을 한 번 하면, **자기 반의 수업만** 시간(요일·교시)마다 나옵니다. 시간마다 하나씩 골라 한 번에 신청합니다.
- 프로그램마다 남은 자리가 보이고, 정원이 찬 수업은 "마감"으로 고를 수 없습니다. 남은 자리는 몇 초마다 새로 읽습니다.
- 여러 시간을 함께 내면 시간마다 따로 판정합니다. 잡은 자리는 바로 확정되고, 그사이 찬 곳만 다시 고릅니다.
- 같은 영역(주제선택끼리, 진로탐색끼리)에서 이름이 같은 프로그램은 기가 달라도 한 번만 고를 수 있습니다.
- 접수 중에는 다른 프로그램으로 옮길 수 있고, 옮기면 먼저 잡은 자리는 풀립니다.

**배정 (한 번에)**
- 묶음 화면에서 **모두 마감 → 배정하기 → 모두 공개** 순으로 넘깁니다.
- 학생이 잡은 자리는 그대로 확정하고, **자리를 못 잡았거나 신청하지 않은 시간만 남은 자리에 무작위로** 채웁니다.
- **전체 배정표**(CSV)로 학생마다 기·영역별 배정을 한 줄로 내려받습니다. 수업별 명단(엑셀·PDF·한글)은 "열기"로 그 시간대에 들어가 받습니다.

**갈 곳 없는 학생이 생기지 않게 하는 방법**
- 누가 자리를 잡을 때마다, 아직 못 잡은 학생 전원이 남은 자리에 겹치지 않게 들어갈 수 있는지 서버가 검사합니다.
- 그 자리를 내주면 누군가 갈 곳이 없어지는 경우에는 정원이 남아 있어도 "다른 학생의 배정에 필요해 고를 수 없습니다"라고 알리고 다른 프로그램을 고르게 합니다.
- 그래서 마감 뒤 무작위 배정에서 전원이 정원 안에서 겹치지 않게 들어갑니다. 배정 뒤에는 전원 배정·정원 이내·참여 제한·겹침 없음을 다시 검증해 검토 화면에 보여 줍니다.
- 조건이 깨졌을 때(접수를 멈추고 정원을 줄인 경우 등)는 아무도 빠지지 않게 조건을 풀어 배정하고 누구인지 검토 화면에 표시합니다.

**시뮬레이션** (`npm run simulate`)
- 정원이 학생 수와 딱 같은 경우, 프로그램 종류가 시간대 수와 같은 가장 빡빡한 경우, 한쪽으로 쏠린 인기, 결석이 많은 경우, 참여 제한, 진로탐색 포함, 시간대마다 다른 목록, 3기, 소규모 등을 무작위로 만들어 끝까지 돌립니다.
- 2026-11-13 이 PC에서 10가지 상황 120번(학생 8~300명) 실행: 갈 곳 없는 학생·겹침·정원 초과 **0건**. 같은 상황에서 자리 잡을 때 검사를 하지 않았다면 120번 중 70번은 겹치지 않게 채울 수 없었습니다.
- 2026-11-14 계산 방식을 손본 뒤 13가지 상황 64번을 다시 실행: 갈 곳 없는 학생·겹침·정원 초과 **0건**(검사가 없었다면 36번은 막힘).

## 학생 화면 미리보기

모집을 열면 화면 오른쪽 아래에 휴대전화 모양으로 학생이 볼 화면이 항상 떠 있습니다(준비 단계에서는 고치는 대로, 그 뒤 단계에서는 저장된 프로그램으로). 자유학기 묶음 안에서는 묶음 전체가, 시간대를 열면 그 시간대가 보이게 미리보기가 따라갑니다. **"접기 / 펼치기"**로 접어 둘 수 있고, 접어 둔 상태는 그 브라우저에 기억됩니다.

- 프로그램 이름·설명·장소·인원을 고치는 대로(저장 전에도) 바로 바뀝니다.
- 자유학기 묶음은 모든 시간대가 한 화면에 나오고, "신청 화면 / 결과 화면"을 바꿔 볼 수 있습니다. 결과 화면은 프로그램을 하나씩 넣은 예시입니다.
- 묶음 카드의 "프로그램 한 번에 넣기"에서도 적는 대로 미리 볼 수 있습니다.
- 미리보기 안에서 눌러 볼 수는 있지만 신청·제출은 되지 않고, 서버에 아무것도 저장하지 않습니다.

## 배정 뒤 고치기 (전출 · 전입 · 배정 바꾸기)

배정 검토·결과 공개 단계의 명단에서 배정을 다시 돌리지 않고 한 명씩 고칩니다.

- **찾기**: 명단 위 칸에 이름이나 학번(1-2-3 또는 10203)을 적으면 그 학생만 보입니다.
- **변경**: 줄 끝의 "변경"을 눌러 다른 프로그램으로 옮깁니다. 프로그램마다 지금 인원/정원이 함께 보입니다.
- **전출 처리**: "변경" 창 아래의 "전출 처리 · 명단에서 빼기". 확인 창을 거쳐 명단과 배정 결과에서 빠지고 신청 기록도 지워집니다(되돌릴 수 없음).
- **전입생 추가**: 학년·반·번호·이름과 프로그램을 골라 넣으면 명단에 더해지고 바로 배정됩니다. 전입생도 같은 주소로 들어와 결과를 봅니다.
- 고칠 때마다 검증 결과가 지금 상태로 다시 계산됩니다. 인원이 정원과 달라지면 "인원이 달라진 프로그램 n개"로 알려 주고, "직접 고침 n건"이 표시됩니다. 누가 언제 고쳤는지는 기록에 남습니다.
- 공개한 뒤에 고치면 학생 화면에도 바로 반영됩니다.
- 자유학기 묶음은 시간대마다 따로 고칩니다(묶음 화면 → 시간대 열기). 다른 시간대와 겹치는지는 확인해 주지 않습니다.

## 대상 학년

- 모집을 만들 때 **대상**을 고릅니다: 전교생 또는 한 학년. 준비 단계에서는 제목 옆 "이름 · 대상 바꾸기"로 고칠 수 있습니다.
- 모집 목록과 제목 옆에 대상이 표시됩니다(예: "1학년 · 접수 중 · 24명").
- 학생 공통 화면 위쪽의 **전체 / 1학년 / 2학년 …** 버튼으로 자기 학년을 고르면, 그 학년 모집과 전교생 대상 모집만 보입니다. 고른 학년은 그 기기에 기억됩니다.
- 대상은 목록을 나누는 표시입니다. 실제로 신청할 수 있는 학생은 그 모집의 명부로 정해집니다.
- 학생 화면 왼쪽 위의 **"목록"**을 누르면 공통 화면으로 돌아갑니다. 교사 화면의 미리보기에서는 공통 화면의 모집을 누르면 그 모집으로, "목록"을 누르면 모집 목록으로 교사 화면이 함께 옮겨 갑니다.

## 학생 공통 QR (접수 중 · 결과 발표 모집 고르기)

모집 목록의 **"학생 공통 QR · 주소"** 하나를 교실에 붙여 두면, 학생이 들어와 지금 접수 중이거나 결과를 발표한 모집을 골라 들어갑니다.

- 접수 중(시작 예정 포함)인 모집은 "신청", 결과를 발표한 모집은 "배정 결과" 아래에 나옵니다. 준비·마감·검토 중인 모집과 열람 기간이 끝난 모집은 나오지 않습니다.
- 모집마다 있는 QR도 그대로 쓸 수 있습니다. **결과는 신청할 때 쓴 것과 같은 QR·주소로 들어가 본인 확인을 하면 나옵니다.**
- 교사 화면의 미리보기: 모집 목록에서는 이 공통 화면이, 배정 검토·공개 단계의 모집에서는 학생 한 명의 결과 화면이 보입니다.

## 학생 문의와 문의함

- 학생은 들어온 화면 아래의 **"선생님께 문의"**로 글을 남깁니다(500자, 한 학생이 한 시간에 다섯 번까지).
- 교사 화면 왼쪽 아래의 **쪽지 버튼**에 새 문의 수가 빨간 숫자로 붙습니다. 30초마다 새로 확인합니다.
- 버튼을 누르면 문의함이 열립니다: 학번·이름, 어느 모집에서 보냈는지, 시각, 내용. 새 문의는 왼쪽에 빨간 줄이 붙고, 열어 보면 읽은 것으로 바뀝니다.
- 문의마다 "지우기"로 지웁니다. 모집을 지워도 문의는 남습니다.
- 답장 기능은 없습니다. 문의처나 교실에서 직접 답해 주세요.

## 결과 명단 보기·내려받기

- **학생에게는 배정된 프로그램과 장소만** 보입니다. 몇 지망으로 배정됐는지, 남은 자리였는지는 교사 화면에서만 봅니다.
- 교사 화면의 명단은 **반별 / 프로그램별**로 묶어 보고, 한 반·한 프로그램만 골라 볼 수 있습니다.
- **명단 내려받기**는 형식을 고른 뒤 학급별·프로그램별을 누릅니다.

| 형식 | 내용 |
| --- | --- |
| 엑셀 (.xlsx) | 첫 시트는 전체, 그다음부터 반(또는 프로그램)마다 시트 하나 |
| PDF (.pdf) | 교실에 붙이기 좋게 꾸민 PDF를 바로 내려받습니다. 반(또는 프로그램) 이름이 크게 나오고, 프로그램마다 색 꼬리표가 붙습니다. 반마다 한 쪽씩 나오며(38명까지 한 쪽), 글꼴이 파일 안에 들어 있어 어느 기기에서 열어도 한글이 그대로 보입니다 |
| 한글 (.hwpx) | 한컴오피스 한글 문서. 반(또는 프로그램)마다 새 쪽에서 시작하는 표 |
| CSV | 예전과 같은 한 장짜리 표 |

예시 파일(가상 명단): `docs/명단_예시/`

## 학생 안내 팝업과 결과 열람 기간

- **입장 전 안내 팝업**: 학생이 QR로 들어오면 입장하기 전에 팝업이 뜹니다. 신청 마감 시각, 들어오는 방법(모집의 입장 방법에 맞춰 자동), 고르는 방법, 배정 방식이 나오고, 교사가 적은 안내문(600자 이내)이 그 아래에 붙습니다. 안내문은 준비·접수 중 화면의 "학생 안내 팝업"에서 언제든 고칠 수 있습니다. 학생은 "안내 다시 보기"로 다시 열 수 있습니다.
- **결과 공개**: 교사가 "결과 공개"를 눌러야 공개됩니다. 학생은 같은 QR 주소에서 본인 결과만 봅니다. 발표 뒤 화면에는 배정된 프로그램, 배정 과정, 내가 낸 희망 목록, 접수번호가 함께 나옵니다.
- **열람 종료 시각**(선택): 배정 검토·결과 공개 화면에서 정합니다. 그 시각부터는 학생이 들어와도 "열람 기간이 끝났습니다"만 보입니다. 비워 두면 기한 없이 볼 수 있고, 나중에 늦추거나 없앨 수 있습니다. 교사 화면의 명단과 내려받기는 기간과 상관없이 남습니다.

## 엑셀 양식으로 한 번에 준비

준비 단계의 **① 양식 받기**로 엑셀 양식(.xlsx)을 내려받아 적은 뒤 **② 작성한 양식 올리기**를 누르면, 읽은 내용을 먼저 보여 주고 **한 번에 적용**합니다. 빈 양식은 [docs/동아리_신청배정_양식.xlsx](docs/동아리_신청배정_양식.xlsx)에도 있습니다.

| 시트 | 적는 것 |
| --- | --- |
| 작성 방법 | 안내만 있음(읽지 않음) |
| 학생 명단 | 학년 / 반 / 번호 / 이름 |
| 프로그램 | 프로그램 이름 / 설명 / 장소·준비물 / 배정 인원 / 최대 인원. 배정 인원을 비우면 학생 수에 맞춰 고르게 나눔 |
| 설정 (선택) | 문의처, 마감 시각(예: 2026-11-20 16:00) |
| 참여 제한 (선택) | 학년 / 반 / 번호 / 이름 / 참여할 수 없는 프로그램 |

- 이미 입력한 명단·프로그램이 있으면 양식에 채워져 내려옵니다. 고쳐서 다시 올리면 됩니다.
- 하나라도 틀린 곳이 있으면 아무것도 바뀌지 않습니다(전부 적용되거나 전부 그대로).
- 적은 시트만 바뀝니다. 프로그램 시트만 적어 올리면 명단은 그대로입니다.
- 양식이 아닌 자기 엑셀을 올려도 명단은 아래 "명부 자동 인식"으로 읽습니다.
- 양식 파일은 구조 검증(압축·XML·패키지)을 통과했고, 사용자가 엑셀에서 정상적으로 열리는 것을 확인했습니다(2026-11-12). 엑셀에서 작성·저장한 파일을 다시 올리는 왕복과 한셀에서의 동작은 아직 확인하지 않았습니다.

## 명부 자동 인식

엑셀 파일(.xlsx)·CSV(UTF-8, 엑셀 한글 CSV)·붙여넣은 표를 읽어 "학년, 반, 번호, 이름"으로 맞추고, **등록 전에 읽은 결과를 먼저 보여 줍니다.**

| 엑셀에 담긴 모양 | 예 |
| --- | --- |
| 칸이 나뉜 표 | 학년 / 반 / 번호 / 이름. 열 순서가 달라도, 연번·성별·생년월일·보호자 칸이 섞여도, 제목 줄이 없어도 읽음. `1학년`·`01`·`5번` 표기도 읽음 |
| 학번 한 칸 | `1학년 1반 5번`, `10105`, `1105`, `1-1-5`, `1.1.5`, `10,105` |
| 학년·반이 한 칸 | `1-3`, `1학년 3반`, `103` + 번호 칸 |
| 반·번호가 한 칸 | 학년 칸 + `3-12`, `0312`, `3반 12번` |
| 한 줄에 전부 | `1학년 1반 5번 김하늘`, `10105 김하늘`, 반별 표의 `5. 김하늘` |
| 반별 명렬표 | 제목 줄 "2026학년도 1학년 3반 학생 명부"나 시트 이름 "1-3"에서 학년·반을 읽음 |
| 병합된 칸 | 학년·반이 빈 줄은 윗줄 값을 이어받음 |
| 좌우로 나란한 표 | 번호 / 이름 / 번호 / 이름 |
| 반이 가로로 놓인 표 | 번호 / 1반 / 2반 / 3반 (칸 안이 이름). 번호 칸이 없으면 위에서부터 순서대로 매기고 그렇게 했다고 알림 |
| 학년(반)이 아예 없는 파일 | 화면에서 한 번 물어 채움 |

- 이름은 `(전입)`·`*` 같은 표시를 떼고, `김 하 늘`처럼 띄어 쓴 이름은 붙입니다. 전출·휴학 표시가 있는 줄은 포함하되 몇 명인지 알려 줍니다.
- 합계·담임 줄, 이름이 빈 줄은 건너뜁니다.
- **짐작하지 않는 값**: `115`(1-1-5인지 1-15인지 모름), 엑셀이 날짜로 바꿔 버린 학번(예: `1-1-5` → `36896`), 범위를 벗어난 숫자, 같은 학년·반·번호의 중복, `가반`·`A반`처럼 숫자가 아닌 반. 이런 줄은 줄 번호와 함께 알려 주고, 하나라도 있으면 등록할 수 없습니다.
- 옛 엑셀(.xls)·한글(.hwp)·PDF는 읽지 못합니다. xlsx로 저장하거나 표를 복사해 붙여넣으세요.
- 파일은 교사의 브라우저 안에서만 읽고, 서버에는 맞춘 결과(학년·반·번호·이름)만 보냅니다.

| 항목 | 이 데모의 기본값 |

| 배정 방식 | 지망 순차 추첨 `RANK_FIRST_LOTTERY_V2` 한 가지만 구현(권장안이며 확정 정책이 아님) |

| 마감 | 마감 시각(선택) 또는 교사가 직접 마감. 서버 시각 기준, 마감 시각과 같으면 거부 |
| 결과 변경 | 공개 뒤 정정 기능 없음(아래 "아직 없는 것" 참고) |

## 구조

```
src/engine.js    배정 엔진(순수 함수, UI·DB와 분리) — 지망 단계 → 잔여 배정 → 불변조건 검증
src/server.js    HTTP API, 인증, 신청 저장(멱등·버전 확인), 상태 전환, 내보내기
src/db.js        SQLite 스키마 (학교별·모집별로 묶인 데이터, 신청 유일성 제약)
src/csv.js       명부 파서(쉼표/탭), CSV 출력(수식 주입 방지)
src/messages.js  엔진 기록 → 학생용 고정 설명 문구
public/          학생 화면(student.*), 교사 화면(teacher.*)
test/            엔진 테스트 11개, API 테스트 10개
scripts/         seed-demo.js(가상 데모), loadtest.js(동시 사용 시험)
```

## 구현한 내부 보호 장치

- 학교 격리: 모든 교사 API가 로그인한 교사의 학교에 속한 모집인지 서버에서 확인(다른 학교는 404). 학생 ID는 세션에서만 결정.
- 학생코드: 서버 보안 난수 8자리(헷갈리는 글자 제외), 서버에는 검증값(HMAC)만 저장, 원문은 발급 직후 한 번만 제공, 재발급 시 이전 코드·세션 폐기.
- 추첨 기준: 접수 시작 때 서버 보안 난수로 한 번 생성·보존, 교사가 고르거나 다시 뽑을 수 없음. 모집당 검증된 배정 실행은 1개(DB 유일성 제약).
- 신청: `(학교, 모집, 학생)` 유일성 제약, 요청 식별자 멱등 처리, 버전 확인, 제출 이력 보존, 서버 저장 뒤에만 '접수 완료' 표시.
- 결과: 비공개로 전부 저장·검증한 뒤 활성 결과 포인터를 한 트랜잭션으로 전환.
- 기타: 응답 `no-store`, CSP, 쿠키 HttpOnly·SameSite=Strict, 다른 출처 요청 거부, 화면은 textContent로만 출력, 주요 동작 기록(`audit_log`).

## 아직 없는 것 (완료했다고 말할 수 없는 것)

- **HTTPS**: 서버 자체는 http입니다. 실제 사용 시 HTTPS 프록시/호스팅 뒤에 두어야 합니다(그 전에는 코드·세션이 암호화되지 않음).
- **학교 공간 개설자 확인**: `SIGNUP_CODE` 외의 소속·권한 확인 절차 없음. 교사 다중요소 인증 없음. 한 학교에 교사 계정 1개(동료 초대·역할 구분 없음).
- **공개 후 결과 정정, 전입·전출 반영**: 화면·절차 없음. 기록(`runs`, `results`, `audit_log`)만 남습니다.
- **엑셀(.xlsx) 파일 직접 업로드**: 붙여넣기와 CSV만 지원. 명단 내려받기도 CSV(엑셀에서 열림)입니다.
- **학생코드 유효기간**, 백업·복구 절차, 개인정보 처리·보유·삭제 운영 문서, 장애 시 기간 조정 기록 화면.
- 입장 방법을 "학번 + 이름"으로 두면 같은 반 학생이 남의 학번으로 신청하는 것을 시스템이 막지 못합니다(기기 고정을 켜도 먼저 들어온 쪽이 차지합니다). 교실에서 함께 신청하는 운영을 전제로 한 선택지입니다.
- 실패한 로그인 횟수 제한은 메모리에만 있어 서버를 재시작하면 초기화됩니다.
- 실제 학생 개인정보로는 사용하지 않았고, 사용 전 위 항목과 문서 11절의 학교별 정책 확정이 필요합니다.
